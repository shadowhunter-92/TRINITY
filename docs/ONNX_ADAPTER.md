# Optional ONNX Runtime CPU adapter

## What it does

This experimental adapter constructs a tiny deterministic two-layer dense neural network **locally** using `onnx` helper functions and runs that model in `onnxruntime` with `CPUExecutionProvider`. No external model weights, downloads, shell commands, or accelerator-specific libraries are involved.

The operation graph is `MatMul → Add → Relu → MatMul → Add`. It uses **float32**, unlike the default Python reference's float64. Comparisons therefore explicitly use `atol=1e-5` and `rtol=1e-4` rather than pretending bitwise parity. All graph initializers and inputs are generated using fixed seeds.

## Installation and execution

The normal offline lab (including tests) does **not** need ONNX packages.

```bash
python -m pip install -e '.[compute-onnx]'
python -m trinitylab.compute benchmark --onnxruntime --batch 8 --repeats 20 --output results/compute_onnx_cpu.json
python -m unittest discover -s tests -p 'test_compute_onnx.py' -v
```

Run from the repository root.

The engine includes list-to-NumPy input conversion and output-to-list conversion in its reported latency. Each backend is warmed up before timed iterations. The report contains package versions, model dimensions, software/timing environment, comparison tolerances, median latency and p95 latency. No inference cost calculation is claimed without actual pricing and utilization data.

## Security and limitations

- CPU-only, no external ONNX file loading or model download.
- A graph generated by this project only; no third-party op extensions or remote execution.
- Numerical tolerance does **not** prove parity across arbitrary models or production workloads.
- This is not a replacement for ONNX Runtime, Triton, TVM, IREE or any other inference engine.
- This task does not prove GPU portability or production cost savings.
- ONNX packages are **optional**; the base test matrix remains offline and dependency-free.

## Test environments

Base suite executes without ONNX dependencies on Python 3.10–3.13. A separate GitHub Actions job installs `.[compute-onnx]` with Python 3.11 and exercises actual ONNX graph creation and CPU runtime checks. If that network-dependent job fails to resolve packages, treat it as a failed optional integration check rather than a pass.
